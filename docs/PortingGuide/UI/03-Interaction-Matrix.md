# UI 操作・インタラクション仕様書 (Java Porting)

## 1. 概要
本ドキュメントは、Horosのビューアにおけるマウスおよびキーボード操作を定義する。特に、操作による「フォーカス(isKeyView)」の状態変化と、それが同期ロジックに与える影響を厳格に定義し、Javaでの実装における挙動の不一致を排除する。

## 2. マウス操作マトリクス

ユーザーの操作に対し、以下の機能が割り当てられる。ツールモード（W, Z, P, M等）によって左ドラッグの挙動が変化する。

| 操作 | 修飾キー | ツールモード | 実行されるアクション | 備考 |
| :--- | :--- | :--- | :--- | :--- |
| **左ドラッグ** | なし | 任意 | **選択中のツールを実行** | W:WL/WW, Z:Zoom, P:Pan, M:Measure |
| **右ドラッグ** | なし | 不問 | **Window Level/Width 調整** | 左右:幅(Width), 上下:レベル(Level) |
| **中ボタンドラッグ** | なし | 不問 | **パンニング (Pan)** | ツールに関わらず画像を移動 |
| **ホイール回転** | なし | 不問 | **スライス移動** | 同期ON時は他ビューアも追従 |
| **ホイール回転** | Alt | 不問 | **ズーム (Zoom)** | 中心点基準の拡大縮小 |
| **ホイール回転** | Shift | 不問 | **高速スクロール** | 5枚単位でのスライス移動 |
| **左ドラッグ** | Ctrl | 不問 | **パンニング (Pan)** | Windows環境向けフォールバック |
| **左ドラッグ** | Alt | 不問 | **ズーム (Zoom)** | ツールに関わらず拡大縮小 |
| **ダブルクリック** | なし | 不問 | **WL/WW リセット** | DICOMタグのデフォルト値へ復帰 |
| **マウス移動** | Shift | 不問 | **拡大鏡表示 & フォーカス取得** | `computeMagnifyLens` を呼び出し、`isKeyView` を YES にする |

## 3. キーボードショートカット一覧

### 3.1 ツールモード切替 (Single Key)
これらのキーを押下した瞬間、ビューアの `currentTool` が変更される。

- **W**: Window Level/Width ツール
- **Z**: ズームツール
- **P**: パンニングツール
- **M**: 長さ計測ツール
- **E**: Repulsor (ROI形状調整) ツール
- **T**: テキスト入力ツール
- **S**: セレクター (標準) ツール

### 3.2 画像操作・ナビゲーション
| キー | アクション | 動作詳細 |
| :--- | :--- | :--- |
| **← / →** | 前後スライス移動 | 1枚単位で移動 |
| **PageUp / Down** | 範囲スライス移動 | 10枚単位で移動 |
| **Home / End** | 端点移動 | シリーズの最初/最後にジャンプ |
| **H** | 左右反転 | Horizontal Flip |
| **V** | 上下反転 | Vertical Flip |
| **Tab** | アノテーション切替 | なし → 図形のみ → 基本 → 全表示 の順にループ |
| **↑ / ↓** | ズームイン/アウト | 段階的な拡大縮小 |

### 3.3 プリセット WL/WW
- **1**: Brain (40 / 80)
- **2**: Bone (300 / 1500)
- **3**: Lung (-600 / 1500)
- **4**: Soft Tissue (40 / 400)
- **5**: リセット (Default)

## 4. フォーカス管理と同期の連鎖フロー (Critical Path)

Java実装において最も注意すべきは、**「いつ `isKeyView` が TRUE になり、いつ同期イベントが飛ぶか」**というフローである。

### 4.1 フォーカス取得フロー
1. **イベント発生**: `mouseMoved` (マウス移動) が検知される。
2. **条件判定**: `Shiftキー` が押下されているか確認。
3. **アクション**: `computeMagnifyLens` (拡大鏡計算) を呼び出す。
4. **状態遷移**: `isKeyView == NO` であれば、`window.makeFirstResponder(self)` を実行。
5. **確定**: `becomeFirstResponder` により `isKeyView = YES` となり、フォーカスが確定する。

### 4.3 フォーカス喪失フロー (Focus Loss)
1. **イベント発生**: マウスがコンポーネント外へ移動 (`mouseExited`) するか、別のビューアがクリックされる。
2. **状態遷移**: `resignFirstResponder` が呼び出される。
3. **確定**: `isKeyView = NO` となり、同期イベントの受信・送信が停止（または制限）される。

### 4.2 同期トリガーフロー
1. **フォーカス確定後**: ビューアが `isKeyView == YES` の状態でスライス移動等の操作が行われる。
2. **通知送信**: `sendSyncMessage` が呼ばれ、他のビューアへ同期イベントを送信する。
3. **受信側処理**: `docs/UI/01-Viewer-Sync-Logic.md` に定義されたフィルタを通過し、画像が更新される。

## 5. 実装上の注意点 (Java Swing)
- **`isKeyView` の再現**: Swingでは `KeyboardFocusManager` や `Component.requestFocusInWindow()` を使用して `isKeyView` 状態を管理する。
- **修飾キーの判定**: `InputEvent.getModifiersEx()` を使用し、Shift, Ctrl, Alt の状態を正確に判定する。
- **マウスイベントの優先順位**: `MouseMotionListener` 内で、ツールモードに応じた処理をディスパッチする設計にする。
