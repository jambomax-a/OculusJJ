# メディア・インポートおよびエクスポート仕様書

## 1. 概要
本ドキュメントは、CD/DVDなどの取り出し可能メディアからのDICOMデータインポート、および患者提供用メディアの作成（エクスポート）機能に関する実装仕様を定義する。

## 2. メディア・インポート・ワークフロー

### 2.1 ドライブ検出メカニズム
OSごとに異なるドライブマウント通知を監視し、メディア挿入時に自動的にインポートプロセスを開始する。

#### Windows
- **戦略**: 定期的なポーリングによるドライブレターの監視。
- **実装**: `WindowsDriveMonitor` クラスにて、`File.listRoots()` を2秒間隔でチェックし、新しいドライブレターが出現したことを検知する。

#### macOS
- **戦略**: `/Volumes` ディレクトリの `WatchService` 監視。
- **実装**: `MacOSDriveMonitor` クラスにて、`ENTRY_CREATE` イベントを検知してボリュームパスを特定する。

#### Linux
- **戦略**: `/media` または `/mnt` の `WatchService` 監視。

### 2.2 スキャン・インポートプロセス
ドライブ検出後、以下の順序でDICOMデータを解析する。

1. **DICOMDIRの探索**: 
   - ルートおよびサブディレクトリから `DICOMDIR` ファイルを優先的に検索する。
   - `DICOMDIR` が存在する場合、そのインデックスに基づき必要なファイルのみを効率的に抽出する。
2. **再帰的ファイルスキャン**:
   - `DICOMDIR` がない、または不完全な場合、全ファイルを再帰的に走査し、DICOMヘッダー（Preamble + 'DICM'）を持つファイルを抽出する。
3. **ユーザー確認**:
   - `DiscMountedDialog` を表示し、ユーザーに以下の選択肢を提示する。
     - **データベースにコピー**: データをローカルストレージにコピーし、DBへ登録。
     - **ブラウズのみ**: コピーせずにビューアで閲覧。
     - **キャンセル**: 何もしない。

### 2.3 dcm4cheによるDICOMDIR解析
`DicomDirParser` は以下の階層構造を走査してファイルリストを作成する。
- `Patient Record` $ → $ `Study Record` $ → $ `Series Record` $ → $ `Image Record`
- 各レコードから `File ID` を取得し、物理ファイルパスを特定する。

## 3. メディア・エクスポート（Burner）仕様

### 3.1 書き出しオプション (`DiscBurningOptions`)
ユーザーが選択可能な書き出し設定を定義する。

| オプション | 説明 | 実装詳細 |
| :--- | :--- | :--- |
| **匿名化 (Anonymize)** | 患者情報を削除/置換 | 指定されたタグ（PatientName等）を空またはダミー値に置換 |
| **圧縮 (Compression)** | 画像データの圧縮方式 | `NONE`, `JPEG`, `JPEG2000` から選択 |
| **ビューワー同梱** | 軽量ビューアの同梱 | `JJDICOMViewer-Lite.jar` および `README.txt` をルートに配置 |
| **レポート同梱** | 診断レポートの出力 | PDF等のレポートファイルを同梱 |
| **HTML出力** | Webブラウザ閲覧用出力 | 静的HTMLおよび画像ファイルの生成 |
| **ZIPアーカイブ** | 全内容をZIP化 | 暗号化オプションおよびパスワード設定をサポート |

### 3.2 出力ディレクトリ構造
出力フォルダは以下の構造を維持する。
```text
[ExportFolder]
├── DICOM/                 # 匿名化/圧縮済みDICOMファイル (00001.dcm, ...)
├── JJDICOMViewer-Lite.jar  # 軽量ビューア (オプション)
├── README.txt              # 操作説明書 (オプション)
├── reports/                # レポートファイル (オプション)
└── DICOMDIR                # 全ファイルのインデックスファイル (必須)
```

### 3.3 書き込み戦略
Java標準APIでは直接のディスク書き込みが困難なため、OS標準のコマンドラインツールを `ProcessBuilder` 経由で呼び出す。

- **macOS**: `hdiutil makehybrid` を使用してISO/DMGを作成。
- **Linux**: `mkisofs` および `cdrecord` を使用。
- **Windows**: 外部ツール（ImgBurn等）へのパスをユーザーに設定させるか、ISOイメージ作成後の外部アプリ起動を推奨。

## 4. 技術的留意事項

- **メモリ管理**: 大量のファイルをスキャンするため、ファイルリストの保持には `ArrayList` ではなくストリーム処理を検討し、メモリ消費を抑える。
- **非同期処理**: ドライブ監視およびインポート処理は `SwingWorker` または専用のスレッドプールで実行し、UI（EDT）をブロックさせない。
- **権限**: 読み取り専用メディアからのコピー時、アクセス権限エラーが発生した場合は適切にスキップし、エラーログを記録する。
