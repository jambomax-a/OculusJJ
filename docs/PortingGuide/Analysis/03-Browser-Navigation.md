# ブラウザ機能分析 (Browser & Navigation Analysis)

## 1. 概要
ブラウザ機能は、患者・検査ツリーの表示、データの検索（Query）、およびスタディ/シリーズ間のナビゲーションを司る。移行においては、Core Data / SQLite を基盤としたデータ管理と UI の同期が鍵となる。

## 2. 主要な导航ロジック (Navigation Logic)
### 2.1 スタディの選択 (`selectStudyWithObjectID:`)
ユーザーが画像やシリーズを選択した際に動作するコアメソッドである。以下の重要な挙動が含まれる：
- **親オブジェクトへの遡上**: オブジェクト（Image/Series）から対応する `DicomStudy` を特定する。
- **データベースコンテキストの動的切り替え (重要)**: 選択されたスタディが現在のアクティブな永続ストアとは異なる場合、コントローラー自身のデータベースインスタンスを自動的に切り替える。これはマルチデータベース環境（複数のPACSからの統合ビュー等）への対応に不可欠な機能である。
- **UIの同期**: `outlineView` の選択位置を更新し、必要な場合にスクロールを行う。

### 2.2 データモデルとの関係
- `DicomStudy`, `DicomSeries`, `DicomImage` を基底とするデータ構造が Core Data (NSManagedObject) として管理されている。
- 複数のデータベースが存在する場合、各データベースは独自のインスタンスとして保持され、選択に応じてコンテキストが遷移する。

## 3. 検索機能 (Search & Query)
### 3.1 遠隔クエリとの連携
`QueryController` と密接に連携しており、dcm4che-net 等を利用した外部 PACS への C-FIND/C-MOVE リクエストを処理する。
- **非同期処理**: `distantSearchThread` を使用し、ネットワーク遅延による UI ブロックを防ぐ設計となっている。
- **フィルタープレデケート**: `fetchPredicate` や `searchString` を用いて検索条件を動的に生成し、フィルタリングを行う。

## 4. Java移行への技術的提言
- **Context Managerの導入**: 複数のデータベースを扱うため、現在のアクティブなコンテキスト（DatabaseInstance）を管理するマネージャー層が必要。
- **ナビゲーションイベントバス**: 選択変更時の UI 更新とデータ同期を一貫させるため、EventBus または Observer パターンを用いたメッセージングを採用すべき。
- **マルチスレッド検索**: Java の `ExecutorService` を使用し、非同期でのクエリ処理を標準化する。
