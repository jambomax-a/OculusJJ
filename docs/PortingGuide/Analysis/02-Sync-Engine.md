# 同期エンジン分析 (Sync Engine Analysis)

## 1. 概要
Horosの同期システムは、`NSNotificationCenter` を使用した Pub/Sub（発行者・購読者）アーキテクチャを採用しています。ユーザーが一方のビューア（例：スライス位置、ズーム、または回転の変更）を操作すると、そのビューアが `OsirixSyncNotification` などの通知を発行し、`userInfo` ディレクトリに指示データを含めます。他のビューアはこれらの通知を購読し、要求された同期操作を実行します。

## 2. 主要な同期メカニズム

### 2.1 通知ベースの通信
システムの中核は、`Notifications.h` で定義されているいくつかの通知定数で構成されています：
- `OsirixSyncNotification`
- `OsirixSyncSeriesNotification`
- `OsirixOrthoMPRSyncSeriesNotification`
- `OsirixViewerDidChangeNotification`

### 2.2 同期指示データ (`userInfo`)
要求される操作を指定するために、通知の `userInfo` で以下のキーが使用されます：
- **ナビゲーション**: `Direction`, `Pos`, `Location`（スクロール/位置合わせに使用）。
- **メタデータ**: `studyID`, `frameofReferenceUID`。
- **データオブジェクト**: `DCMPix *oPix`, `DCMView *otherView`。
- **3D座標**: `point3DX`, `point3DY`, `point3DZ`（3D座標の同期用）。
- **同期タイプ**: `syncro`（絶対位置、比率、または場所ベースなどの同期タイプを表す整数）。

### 2.3 `DCMView.m` におけるコアロジック
`DCMView` 内の `sync:` メソッドは以下の指示を処理します：
- **再帰の回避**: 二つのビューア間で通知が往復して無限ループに陥るのを防ぐため、`avoidRecursiveSync` カウンタを使用。
- **絶対位置 / 比率同期**: シリーズの総画像数に対する提供されたオフセットまたは比率に基づき、現在の画像インデックスを直接設定。
- **場所ベースの同期 (複雑)**: 
    - `angleBetweenVector` を使用してビュー間の平面の向きを比較。
    - 平面が許容誤差内（並行）である場合、相手のビューの平面上の要求位置に対応する最近接のスライスまたはポイントを計算。
    - MPRボリュームが含まれる「Volume」モードも処理。

### 4. Javaへの実装戦略
- **イベントバス**: これらのビューア間メッセージを処理するために、Javaでオブザーバーパターンまたは中央集中型のイベントバスを使用。
- **指示オブジェクト**: `userInfo` ディレクトリ内のすべてのキーをカプセル化した `SyncInstruction` クラスを作成。
- **状態管理**: 各ビューアが独自の独立した状態（画像インデックス、行列など）を保持しつつ、同期イベントを介して更新されるようにする。
- **スレッドの安全性**: Javaにおいてこれらの通知がバックグラウンドスレッドからUI更新をトリガーする可能性があるため（フレームワークによる）、すべてのビュー更新が適切なスレッドにディスパッチされることを保証する。
