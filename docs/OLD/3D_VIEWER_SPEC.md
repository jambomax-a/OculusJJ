# OculusJJ 3D Viewer 機能仕様書 (DOCS-3D-001)

## 概要
OculusJJの3Dビューワーモジュールは、DICOMボリュームデータ（CT/MRI/PET等）をリアルタイムで三次元可視化するための高度な統合コンポーネントです。
HOROS-20240407 (DCM Framework / VRController.m) の最高仕様に準拠し、**LWJGL 3 (OpenGL 3.3 Core Profile) を用いた超高速GPUボリュームレイキャスティング**と、**CPUベースのマルチスレッド・ソフトウェアレイキャスティング（堅牢なフォールバックエンジン）**を組み合わせたハイブリッドレンダリングアーキテクチャを実現しています。

---

## 1. ハイブリッド・レンダリングエンジン

### 1.1 GPUレンダリング (主エンジン: OpenGL 3.3 Core Profile)
- **コア技術**: 3Dテクスチャサンプリングによる GPU Volume Ray Casting 法。
- **データテクスチャ**: 
  - **Volume Texture (GL_TEXTURE0)**: 符号付き 16-bit DICOM生データを `GL_R16F` (浮動小数点数赤単一チャンネル) 3Dテクスチャに焼き付け。シェーダー内でリアルタイムに物理 Hounsfield Unit (HU) 値（`raw = tex * 65535.0 - 32768.0`）へデコード。
  - **Gradient Texture (GL_TEXTURE1)**: 立体形状の陰影（法線ベクトル）を高精度に描画するため、Sobelフィルタで事前計算された三次元勾配（$dx, dy, dz$）を `GL_RGBA8` 3Dテクスチャとしてバインド。
  - **Transfer Function Texture (GL_TEXTURE2)**: カラーと不透明度の伝達関数を格納する 1Dテクスチャ (`GL_RGBA16F`)。`-1024`〜`3072` HUの全物理範囲を網羅し、毎フレームのテクスチャ再ロード負荷を完全に排除。
- **シェーダーコード**: `GLViewer3D.java` 内にインライン展開された GLSL (#version 330 core)。
- **物理座標系 (Anisotropic correction)**: スライス厚とピクセル間隔（X, Y, Z spacing）を DICOM メタデータから取得し、モデル行列のスケールを正規化することで、ボクセルの扁平化・歪みを完全に補正（HOROS同様の物理サイズ比 1:1 表示）。

### 1.2 CPUレンダリング (堅牢な自動フォールバックエンジン)
- **並列処理**: Java 8 `IntStream.range().parallel()` による CPU コア全スレッド最大並列化ソフトウェアレイトレーサー。
- **データ構造**: 一次元統合 `short[]` 配列によるキャッシュフレンドリーな高速ボクセルアクセス。
- **特徴**: OpenGLコンテキストの作成失敗、OS依存のドライバー不具合、リソース枯渇時に自動でCPUエンジンへシームレスにフォールバック。GUIスレッドをフリーズさせないバックグラウンド・ワーカースレッド実行。

## 2. 実装されている3Dモード

`Viewer3DController.java` にて、以下のモードがGPU・CPUの双方で正確に切り替え可能であり、メニュー選択時に遅延なく瞬時に再描画されます。

### 2.1 MIP (Maximum Intensity Projection: 最大値投影)
- **原理**: 視線レイ上のボクセル値の中で、WL/WW窓でスケールされた最大輝度をサンプリング。
- **用途**: 造影血管、骨、石灰化の三次元構造をクリアに描画。
- **輝度調整**: 窓関数による補正を適用し、背景ノイズとコントラストを微調整可能。

### 2.2 VR (Volume Rendering: ボリュームレンダリング)
- **原理**: 伝達関数（不透明度＋カラー）をレイ上でアルファブレンディング（積分計算）し、Blinn-Phong反射モデルを適用。
- **ライティング**:
  - **Ambient (環境光)**: `0.20`
  - **Diffuse (拡散反射光)**: `max(dot(N, L), 0.0) * 0.90` (法線 $N$ は勾配テクスチャからデコードした外向きベクトル)
  - **Specular (鏡面反射光)**: `pow(max(dot(N, H), 0.0), 15.0) * 0.30` (Blinn-Phongハイライト)
- **プリセット**: `"VR Muscles-Bones"` プリセットを搭載。筋肉等の軟部組織は暖かみのある暖色系オレンジ・赤のグラデーション、骨格は美しい高精細な乳白色（`R=255, G=245, B=240`）でリアルに描画。

### 2.3 ISO (Surface Rendering: 等値面・サーフェスレンダリング)
- **原理**: 設定された閾値 (`isoThreshold`) にレイが最初に到達した境界点を等値面（Surface）とし、その位置の法線ベクトルを用いて3D陰影を計算。
- **用途**: 骨格表面、あるいは皮膚・臓器境界の頑健な立体把握。

## 3. マウスインタラクションとジェスチャー操作 (HOROS準拠)

マウスのドラッグ操作と3D空間の同期について、数学的アプローチによる完璧な操作フィーリングを実現しています。

### 3.1 3D回転 (Rotate)
- **ジェスチャー**: 左ボタンによるドラッグ。
- **挙動**: 水平ドラッグ（`dx`）でY軸周りの回転、垂直ドラッグ（`dy`）でX軸周りの回転。

### 3.2 完璧なスクリーン整合パニング (Pan)
- **ジェスチャー**: 中ボタン（ホイールクリック）またはドラッグ中に `Shift`/`Ctrl` なしでの平行移動。
- **座標射影アルゴリズム**:
  傾いた3Dビューポート上でマウスを動かした際、画像の移動方向が100%直感的に手の動きと同期するよう、カメラのUp/Rightベクトルをボリュームの回転座標上に動的に射影。
  - **Camera Up (ボリューム空間)**: $U_{vol} = (0, \cos(\theta_x), -\sin(\theta_x))$
  - **Camera Right (ボリューム空間)**: $R_{vol} = (\cos(\theta_y), \sin(\theta_y)\sin(\theta_x), \sin(\theta_y)\cos(\theta_x))$ (※ 回転行列の乗算に基づき正確な正の符号に補正)
  - **移動計算**: 
    画面のドラッグ方向と同期させるため、レイキャストサンプリング座標系（`vTex + uOffset`）におけるズレを補正するマイナス符号（`-dx`）を適用。
    $$\Delta Offset = -dx \cdot R_{vol} + dy \cdot U_{vol}$$
  - **効果**: ボリュームがどのような角度に回転していても、マウスを「上・下・左・右」に動かした方向と画面上の物体の移動が完璧に1:1で同期。

### 3.3 ズーム (Zoom)
- **ジェスチャー**: マウスホイールスクロール、または `Shift`/`Ctrl` + 左ドラッグ。
- **挙動**: 投影行列および視界（FOV）スケールを制御し、滑らかに拡大・縮小。

### 3.4 リアルタイム WW/WL 調整 (明るさ・コントラスト)
- **ジェスチャー**: 右ボタンによるドラッグ。
- **数理的窓関数適用**:
  - **初期窓値**: 3Dボリュームレンダリングに最も適した **`WL = 1024 / WW = 4096`** を起動デフォルト値に設定。これにより、2D用の狭い窓による「肉付き剥がれ（痩せ細りバグ）」を完全防止し、初画面から美しい軟組織と骨を両立描画。
  - **GPUサンプリング**: シェーダー内で窓関数（`tfT = clamp((raw - winLow) / WW, 0.0, 1.0)`）を動的に評価し、静的な転送関数テクスチャをサンプリング。
  - **再描画トリガー**: 左右/上下ドラッグによるWW/WLの調整時、`repaint()` をOpenGLおよびAWTスレッドに強制配信。
  - **効果**: 右ボタンをドラッグすると、筋肉の肉付き度合いやコントラストが**リアルタイムかつ超スムーズに明るく・暗く追従変化**します。

---

## 4. 解剖学的方位マーク (Orientation Cube)

- **UI要素**: ビューポートの右上隅に緑色の立方体枠と解剖学的方位インジケータ（**A**nterior, **P**osterior, **S**uperior, **I**nferior, **R**ight, **L**eft）を描画。
- **空間同期**: メインボリュームと完全に同期した回転行列（`model`）を適用し描画。現在の方向が一目で識別可能。

---

## 5. ロバストネス (堅牢性) 設計

1. **OpenGLスレッド・セーフティ**: AWT/EDTスレッドとOpenGLコンテキスト切り替え時のリソース競合を完全に排除するため、GL描画ライフサイクルを完全に `paintGL()` の EDT パスで制御。
2. **GPUアクティベーション防護 (Watchdog)**: GPUスレッドのフリーズやハングを検知する 12秒制限 of タイマー監視を搭載。異常検知時は速やかに安全なCPUモードへフォールバック。
3. **動的メモリ管理**: 不要になったスライスメモリをHU変換後に即座に破棄し、100枚ごとのGCクリーンアップを行うことで、大規模スタディ読み込み時の OutOfMemoryError を物理的に回避。
